# Deployment model artifacts

The trained 5-seed ensemble (`weights/model_seed_{0..4}.pt`) and its scaler
(`scaler/robust_scaler.joblib`, `scaler_metadata.json`, `shap_background.npy`) —
copied from the `MLimplement` branch's `ml/artifacts/`, ~6MB total.

`artifacts/` at the repo root is gitignored on purpose: it is a *build output*
directory, regenerated by training runs and not meant to be reviewed as source. This
directory is the deliberate exception — a fixed, versioned copy small enough to commit,
baked into the Docker image by the `Dockerfile` so a platform with no shared or
persistent filesystem between services (Render) needs no separate artifact-transfer
step (scp, a disk upload, external object storage) to serve real predictions.

To ship a retrained ensemble: replace the files here with the new
`ml/artifacts/weights/*.pt` and `ml/artifacts/scaler/*`, commit, and redeploy — the
Docker build picks them up automatically. Keep `config/default.yaml`'s
`predictor.config_path` pointed at the ML config the checkpoint was actually trained
with (seed count and model hyperparameters must match, or the ensemble silently loads
fewer members than expected).
